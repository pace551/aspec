# Glossary

Shared vocabulary for the governance framework. Standards and skills use these terms with
exactly these meanings.

## RFC-2119 requirement levels

| Term | Meaning |
|---|---|
| **MUST** / **MUST NOT** | Absolute requirement/prohibition at the tiers where the rule is `required`. Violations block "done" unless waived. |
| **SHOULD** / **SHOULD NOT** | Strong default. Deviating is allowed with a stated reason (in code review notes or GOVERNANCE.md attestation), no waiver needed. |
| **MAY** | Genuinely optional; listed to mark the option as sanctioned. |

## Tier codes

`T1` personal · `T2` research · `T3` product · `T4` commercial — see `tiers.md`.
Frontmatter applicability values per tier: `required`, `advisory`, `n/a`.

## Enforcement layers

Every normative rule declares how it is backed:

| Code | Layer | Mechanism | When it fires |
|---|---|---|---|
| **H** | Hard hook | Claude Code PreToolUse hook, git pre-commit/pre-push hook | Blocks the action itself, before it happens |
| **G** | Gate | CI job, `/verify-compliance` check | Blocks "done"/merge/deploy after the fact |
| **A** | Advisory | Manifest attestation in `GOVERNANCE.md` via `/verify-compliance` checklist | Never blocks; makes drift visible and reviewable |

A rule may have multiple layers (e.g. secrets: H pre-write hook + G gitleaks CI job).
"Advisory-only" families still pass through the forced attestation checklist — advisory
means *unblocked*, not *invisible*.

## Identifiers

- **Standard ID** — `FAMILY-SHORTNAME` (e.g. `SEC-SECRETS`, `STK-PY`). Stable forever;
  renaming a standard means deprecating the old ID.
- **Rule ID** — `{STANDARD-ID}-NN` (e.g. `SEC-SECRETS-01`). Never renumbered; retired rules
  keep their number with status *retired*. Waivers and GOVERNANCE.md reference rule IDs.
- **Family codes** — `SEC` security · `TST` testing · `ARC` architecture · `STK` stacks ·
  `INF` infrastructure · `OPS` operations · `DEV` process · `UX` UI/UX · `DATA` data
  governance · `AI` LLM concerns · `LEG` legal/commercial.

## Framework artifacts

| Term | Meaning |
|---|---|
| **Constitution** | `constitution/CONSTITUTION.md` — always-loaded invariants (articles C1–C10). |
| **Standard** | One file in `standards/` following `templates/standard-template.md`. |
| **index.json** | Machine catalog generated by `checks/build-index.py`; `/govern`'s entry point. Never hand-edited. |
| **GOVERNANCE.md** | Per-project manifest: tier, stacks, pinned standard versions, waivers, attestations, `last_verified`. |
| **Waiver** | Recorded exemption from a required rule: `{rule_id, reason, expires}`. Expiry mandatory; expired waivers fail `/verify-compliance`. |
| **Selected set** | The standards `/govern` loads for a task: constitution + index filter on tier/stacks/triggers + transitive `requires` (capped at two hops). Brief mode loads each standard's frontmatter + Abstract + Rules + Verification only. |
| **Ratchet** | A metric baseline committed to the repo that may only improve (e.g. `.coverage-baseline`). |
| **Attestation** | Explicit yes/no self-report against an advisory rule, written into GOVERNANCE.md by `/verify-compliance`. |

## Status values

Standards: `draft` (not yet enforceable) → `active` → `deprecated` (kept for pinned
projects; index marks it, `/govern` won't select it for new work).
Rules: `active` | `retired`.
Vault learnings: `candidate` → `promoted` | `rejected`.
